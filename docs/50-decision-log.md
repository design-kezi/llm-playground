### 2026-10-24: 판단 모델 선정 테스트 v2 — 사전 등록 (결과를 보기 전에 고정)
사용자 결정: Gemini 결제 연결(유료 등급). B단계는 A단계 상위 5개 모델만. 결과는 문서로 남김. 사용자 지시: "하지 않은 테스트로 모델을 정하지 말 것, 추측하지 말 것, 데이터는 있는 그대로 둘 것."

**A단계: 오프라인 판단 정확도와 비용**
- 후보 11개: claude-haiku-5-5, gpt-5-nano, gpt-6-luna, gpt-4.1-nano, gemini-3.1-flash-lite, gemini-3.5-flash-lite, deepseek-flash, gemma-4-26B-A4B, gemma-4-31B, Qwen3-32B, Llama-3.1-8B. 사전 호출 11/11 정상(2026-10-24 01시대).
- 데이터(`model/judge/v2/data/`):
  - v1 한국어 데이터(옛 캐릭터 3개 대본 + 손으로 쓴 어려운 문항)는 그대로 둔다.
  - 새 캐릭터 4개(baekho, naruto, backend, sejong) 대본을 추가한다. 이전 턴 응답과 기억 항목은 nc8 mem-1 런에서 가져온다.
  - 정답 라벨은 v1과 같은 규칙으로 정한다. 저장 판단은 대본의 턴 종류(plant/update/retract/distractor, 1턴)로, 꺼내기 판단은 probe 여부로, 수정 대상은 probe의 source_turns 사슬로 정한다. 수정 대상 문항에서 정답이 '없음'인 것은 distractor 턴과 plant 턴(새 정보)이다.
  - 조정 세션이 수정 대상 문항을 손으로 더 쓴다. 이 문항은 사람이 검수하지 않았다고 표시한다.
  - 다른 언어(zh-TW, ja, en)는 v1과 같은 방식으로 Haiku가 번역하고, 문자 검사를 통과한 것만 쓴다. 번역은 사람이 검수하지 않는다.
- 호출: v1 프롬프트를 그대로 쓴다(문항 10개 묶음, JSON, max_tokens 400). 추론은 `pricing.json`의 off 설정을 따른다(gpt-5-nano는 minimal). 모델 × 언어마다 3회 반복한다.
- 채점:
  - 무응답과 파싱 실패는 **오답**으로 센다(v1은 이진 과제에서 무응답을 '아니요'로 처리했다).
  - 저장·꺼내기는 F1, 수정 대상은 **균형 정확도** = (바꿀 항목이 있는 문항의 정답률 + 정답이 '없음'인 문항의 정답률) ÷ 2. 둘 다 따로 표기한다.
  - 언어별, 출처별(v1 대본·새 대본·손으로 쓴 문항), 3회 평균과 범위를 표기한다.
- 비용: 장부의 실제 cost_krw(1,400원/$)를 쓴다. 판단 1,000건당 원으로 환산한다. DeepSeek은 실제 시간대 단가와 정가 환산을 함께 적는다.
- **B단계 후보 선정 규칙(상위 5개):**
  - 자격: 무응답·파싱 실패율 5% 이하.
  - 점수: 4개 언어 평균 × 3과제 평균(저장 F1, 꺼내기 F1, 수정 대상 균형 정확도), 3회 평균.
  - 동점(0.5%p 이내)이면 비용이 낮은 쪽.
  - 비용은 순위에 넣지 않고 표에 함께 보여 사용자가 판단한다.
- 결과를 본 뒤 라벨을 고치지 않는다. 라벨 오류로 보이는 문항은 목록으로 따로 보고하고, 점수는 원래 라벨 기준으로 낸다.
- 주의: A단계는 실제 추출 호출이 아닌 대리 과제다. 실제 파이프라인에서 저장·꺼내기는 지금 규칙(정규식)이 판단하고, LLM 추출기가 저장할 내용과 수정 대상을 정한다.

**A단계 실행 기록**

## 실수와 원인

1. **판단 모델 평가 결과를 반영하지 않았다.** Haiku가 수정 대상 찾기에서 최하위권이었는데도 추출 모델로 계속 썼다. 이후 r1~nc10 동안 고친 버그 중 상당수(B21, B33, B42 등)가 바로 그 과제에서 나왔고, 코드 방어를 쌓다가 설계 문제로까지 이어졌다. 모델을 바꿨다면 줄었을지는 실측해야 할 가설이다.
2. **대화 모델 비교를 한 번도 하지 않았다.** 벤치 계획 단계 1(6개 모델 1차 선별)을 건너뛰고, Haiku로 바로 비용 낮추기와 버그 수정에 들어갔다.
3. **원인:**
   - 세션을 레이어별로 나눠서 "판단 모델 확정 → 대화 모델 비교" 관문을 책임지는 쪽이 없었다.
   - 초기에 안정적으로 돌아가는 제공사가 Anthropic뿐이라 Haiku로 시작했는데, 이것이 임시 선택이라는 점이 잊혔다.
   - 측정 → 버그 → 수정 → 재측정 순환이 전제 점검을 밀어냈다.
4. **조정 세션의 실수:**
   - 브리핑할 때 판단 평가 리포트를 확인하지 않았다.
   - "Haiku로 확정했다면"이라고 말해 모델 선정을 거친 것처럼 전달했다.
   - 다른 모델의 비용을 계산값으로만 제시하면서, 실측이 하나도 없다는 점을 먼저 밝히지 않았다.
5. **수치 신뢰성 관련(이미 버그 목록에 기록됨):** 미채점 문항을 빼고 점수를 냄(A1), 기억 단독 벤치를 앱과 다른 방식으로 돌림(A10), AI 판정관에게 엉뚱한 턴의 기억 블록을 넘김(B43, 이전 판정 18건 무효), 같은 응답에 판정이 흔들림(A15).
