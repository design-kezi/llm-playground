# [엔지니어 과제] 1턴 1원 이하의 라이트 모드

> 원문 요약본. 이 과제는 지원자가 주어진 문제를 어떻게 바라보고, 어떤 기준으로 선택하고 결정하는지 알아보기 위한 것이다. 정해진 정답은 없다. 비용과 대화 품질 사이에서 무엇을 중요하게 생각했는지, 어떤 근거로 제안에 이르렀는지를 설명한다. 모호한 부분은 직접 정의해도 되며, 모든 것을 완성하기보다 선택한 방향과 이유를 보여줄 자료를 준비한다.

## 과제 목표

**1턴당 평균 AI 비용 1원 이하로, 사용자가 계속 대화하고 싶은 무료 롤플레잉 채팅 모드 '라이트 모드'를 제안한다. 구현 또는 설득력 있는 대체 자료로 실현 가능성을 보여준다.**

운영 비용을 최대한 낮추면서 이익을 남길 수 있는 지속가능한 채팅 모드가 목적이다. 캐릭터와 대화하는 재미와 최소한의 장기 기억력을 유지하면서 비용을 최대한 낮춘다.

## 필수 조건

### 1. 평균 비용은 1턴당 1원 이하, 저렴할수록 좋다
- 1턴 = 사용자 메시지 1개 + 캐릭터 답변 1개가 완료되는 단위
- 평가 대화 전체의 AI 비용 ÷ 완료된 턴 수 = 평균 비용
- 입력·출력 토큰, 요약, 기억 추출·검색용 AI 호출, 임베딩, 재시도 및 실패한 호출 비용을 모두 포함
- 일부 턴이 1원을 넘는 것은 허용. 전체 평균과 함께 대화 초반·중반·후반 비용, 최대 턴 비용을 제시
- 무료 크레딧·일시적 프로모션은 비용 절감으로 계산하지 않음. 모델 가격의 출처·기준일, 원화 환산 기준 명시
- 자체 호스팅 시 추론 인프라 비용과 사용량 가정 제시. 보유 장비라고 0원으로 계산하지 않음
- 일반 서버·저장소 등 AI 외 운영비는 1원 기준과 분리해 추정

> 1원은 목표의 끝이 아니라 상한이다. 필수 품질을 충족하면서 더 낮은 비용을 달성한 설계를 높게 평가한다.

### 2. 응답 길이는 자유
최소 글자/토큰 제한 없음. 짧아도 된다. 분량 자체는 가점이 아니며, 상황에 맞는 반응과 대화를 이어가고 싶은 경험을 평가한다.

### 3. 기본적인 롤플레잉
- 캐릭터의 성격·말투·설정 유지
- 사용자의 말과 현재 상황에 맞는 반응
- 반복적인 맞장구에 머물지 않고 대화나 상황을 이어감
- 사용자의 행동이나 감정을 일방적으로 확정하지 않음

### 4. 최소한의 장기 기억
최근 몇 개 메시지에 없는 중요한 정보를 이후 대화에서 활용할 수 있어야 한다. 모든 내용을 기억할 필요는 없다. 최소한 다음을 검증한다(구현이 어려우면 설계와 평가 사례로 설명).

1. 앞서 이야기한 사용자 정보나 선호를, 다른 주제가 충분히 이어진 뒤에도 기억한다.
2. 캐릭터와 사용자 사이의 중요한 사건이나 약속을 이후 대화에 반영한다.
3. 사용자가 기존 정보를 수정하면 오래된 정보 대신 수정된 정보를 반영한다.
4. 대화에 없었던 정보를 기억하는 것처럼 만들어 내지 않는다.

'얼마나 오래', '무엇을 중요하게', '어느 정도 성공하면 충분한지'는 직접 정의해도 된다. 기준과 이유를 설명하고, **바로 앞 메시지를 읽는 것만으로 통과할 수 없는 평가 사례**를 만든다. 기억 관련 처리 비용도 전체 AI 비용에 포함한다.

## 구현 범위와 재량
- 모델, 프롬프트, 기억 방식, 기술 스택 자유. 여러 모델 조합 가능
- 모호한 조건은 스스로 정의하되, 가정·선택 이유·가정이 달라질 때의 한계를 밝힌다. 모호함을 검증 가능한 문제로 바꾸는 능력도 평가 대상
- 구현 시 API 호출만으로 여러 턴 대화와 장기 기억 검증이 가능하면 충분(로컬 실행 가능). 프론트엔드/UI는 불필요하며 평가에 반영하지 않음. 실제 서비스 연동·결제 불필요
- GPU/서버 비용 등으로 실제 구축이 어렵다면 설계도·의사코드·비용 계산·부분 실험 등으로 대체 가능. 유료 인프라를 대여할 필요 없음

## 제출물

### 1. 프로토타입 또는 대체 자료
- 구현 시: 소스 코드, API 실행 방법, 필요한 설정, 요청·응답 예시. curl 또는 간단한 호출 스크립트로 평가자가 여러 턴 대화와 장기 기억 동작을 확인할 수 있게 안내. **API 키 등 비밀값은 포함하지 않는다.**
- 대체 자료 예: 공식 가격표 링크와 모델 선택 이유 / 턴당 비용 계산 / 직접 시도한 롤플레잉 예제와 프롬프트 / 기억 실험 / 설계도·핵심 로직 의사코드
- 모든 자료를 낼 필요는 없으나, 어떤 모델과 방식으로 어느 정도 비용에 어떤 품질과 기억력을 제공할 수 있는지 납득 가능하게 조합한다. 가격표만 첨부하지 말고 자기 대화 조건에 적용한 계산과 예제를 연결한다.
- 외부 자료는 출처 표시. **실제 실행 결과와 예상 동작·미검증 사항을 구분**한다.

### 2. 비용 측정 또는 추정 근거
- 대화 시나리오, 턴 수, 전체 AI 비용, 평균 및 구간별 턴 비용
- 구현했다면 실측, 아니면 가격 출처와 입출력량·기억 처리 빈도·인프라 사용량 가정을 포함한 계산 근거
- 실측과 추정을 명확히 구분. 요약처럼 간헐적인 작업도 계산에서 빠뜨리지 않는다.

### 3. 품질·장기 기억 평가
- 평가 기준과 대화 사례. 구현했다면 실제 응답과 성공·실패 사례, 대체라면 시나리오·기대 동작·판정 기준
- 직접 작성한 기대 응답과 실제 모델 출력을 구분
- 캐릭터성, 맥락, 대화 지속성, 장기 기억을 어떻게 판단할지 설명. 확인한 내용과 추가 검증이 필요한 내용을 밝힌다.

### 4. 설계 판단과 다음 실험 (간결하게 답변)
1. 왜 이 방식을 선택했고, 어떤 대안을 포기했나?
2. 비용을 낮추면서 어떤 품질을 유지하고 어떤 품질을 양보했나?
3. 대화가 더 길어지거나 사용 패턴이 달라지면 어디서 문제가 생기나?
4. 실제 사용자가 계속 대화하고 싶어 하는지 확인하기 위해 가장 먼저 어떤 실험을 하겠나?

## 평가 관점

| 관점 | 내용 |
| --- | --- |
| 비용 효율 | 평균 1원 이하를 충족할 근거, 필수 품질 유지하며 얼마나 더 낮출 수 있는지 |
| 대화 경험 | 캐릭터와 대화하는 느낌, 다음 대화를 이어갈 이유 (응답 길이는 평가 안 함) |
| 장기 기억 | 직접 정의한 기준의 타당성, 최근 문맥 밖 정보를 활용하는 방식과 근거의 구체성 |
| 근거의 신뢰성 | 실측·추정·미검증 구분, 계산과 검증 방법의 재현 가능성 |
| 판단력 | 모호한 요구의 구체화, 비용-품질 선택의 설명 |

> 실제 구축 여부나 자료 형식보다, 제안한 모드를 실현할 수 있다는 근거의 구체성과 설득력을 평가한다. 검증하지 못한 부분은 솔직히 밝히고 확인 방법을 설명한다. 자체 평가만으로 사용자 재미가 입증됐다고 볼 필요는 없으며, 확인한 사실과 실제 사용자 검증이 필요한 가설을 구분한다.
