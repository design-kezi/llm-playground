## 3. 계획

### 3.1 전체 원칙
1. **탭마다 같은 틀**: ① 결론 한 줄(제목) ② 핵심 숫자 카드 2~4개 ③ 근거 그림 1~2개 ④ 표(세부) ⑤ 접힌 세부. 요약 탭은 다섯 탭의 ①②를 모은 것.
2. **기준 숫자 하나**: 모든 결과는 최종 구성(lt8) 기준. 비교가 필요하면 같은 회차 비교만 쓰고, 이력(①②)은 설계 구조 탭 '어떻게 여기까지 왔나' 한 곳에만.
3. **섹션 제목 = 결론 문장**(예: "120턴 평균 0.372원 — 1원의 37%").
4. **글**: 한 문장 한 사실, 괄호 최소, 같은 정보 반복 금지. 실측/추정/미검증 배지는 숫자 카드·표의 근거 열에만.
5. **도식은 SVG로 직접**: 상자=요소(이름+역할+기술), 화살표=라벨 필수, 실선=동기, 점선=백그라운드, 범례 1개.

### 3.2 탭별 구성

### 3.3 구현
- `ui.js`: 차트 컴포넌트 재작성 — `BarChart`(가로, 0 기준, 강조형, 직접 라벨, 실선 기준선+축 위 라벨), `Columns`(구간별), `Stacked`(구성), `Dumbbell`(전후), `Kpi`, `Verdict`(✓/✗+글자).
- `diagrams.js`: SVG 다이어그램 4개 재작성(컨테이너도, 시퀀스, 기억 두 경로, 검증 파이프라인) + 프롬프트 쌓기. 화면 폭이 좁으면 가로 스크롤 대신 축소(viewBox).
- `views.js`: 탭별 틀로 재작성. 데이터는 data.json 그대로.
- `globals.css`: 리포트 영역만 정리(위계: 제목 결론 → 카드 → 그림 → 표).
- 검사: 빌드 → /report/all 렌더 → 탭별 스크린샷(데스크톱 1280·모바일 390) → 도식 체크리스트·차트 반패턴 대조 → 숫자 대조(data.json vs 화면).
