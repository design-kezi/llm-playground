# 학습 1. LLM API의 기본 동작 원리

이 과제에서 "비용"과 "기억"은 모두 이 장의 내용에서 나온다.

## 1. 토큰
- 모델은 글자가 아니라 **토큰** 단위로 텍스트를 읽고 쓴다. 비용도 토큰 수로 계산한다.
- 영어는 대략 단어 1개 ≈ 1~1.5토큰. 한국어는 같은 의미를 담는 데 토큰이 더 많이 든다(모델/토크나이저마다 다름).
- 따라서 **한국어 롤플레잉은 영어 기준 추정치보다 비싸다**. 비용 계산은 반드시 실제 한국어 텍스트의 토큰 수로 한다.
- 토큰 수는 추측하지 말고 API 응답의 `usage`로 확인한다.

## 2. API는 상태가 없다 (stateless)
- 모델은 이전 호출을 기억하지 못한다. "대화"는 **매 요청마다 이전 메시지를 전부 다시 보내서** 만들어지는 착시다.
- 요청 구조(공통 개념):
  ```
  messages = [
    {role: system,    content: 캐릭터 설정 + 규칙},
    {role: user,      content: 1턴 사용자 말},
    {role: assistant, content: 1턴 캐릭터 답},
    ...
    {role: user,      content: 현재 사용자 말},
  ]
  ```
- 결과: 턴 N의 입력 토큰은 대략 `시스템 + (N-1턴 분량의 누적 대화) + 현재 메시지`. **대화가 길수록 한 턴 비용이 선형으로 증가하고, 누적 총비용은 제곱으로 증가한다.**
- 이 과제의 본질은 "이 누적을 어떻게 막으면서 기억은 유지하느냐"이다. 장기 기억 설계(학습 5)가 곧 비용 설계다.

## 3. 입력 가격 vs 출력 가격
- 대부분의 제공업체는 입력과 출력 토큰 단가가 다르고, **출력이 더 비싸다**(보통 수 배).
- 하지만 롤플레잉은 입력이 훨씬 길다(캐릭터 설정 + 기억 + 최근 대화). 그래서 보통 총 토큰의 대부분은 입력이고, 입력 줄이기와 캐시 활용이 효과적이다.
- 응답 길이는 자유라는 조건 = 출력 토큰을 줄일 여지가 있다는 뜻이다. 다만 짧기만 하면 대화 경험이 나빠지므로 품질과 균형을 본다.

## 4. 컨텍스트 윈도우
- 한 요청에 넣을 수 있는 최대 토큰(입력+출력). 최신 모델은 매우 크지만 **크다고 다 넣으면 비용이 폭발**한다.
- 이 과제에서 한계는 윈도우 크기가 아니라 "1원"이라는 예산이다.

## 5. 프롬프트 캐싱
- 요청 앞부분(접두사)이 이전 요청과 동일하면 그 부분을 할인 단가로 처리해 주는 기능(제공업체마다 조건·할인율·캐시 쓰기 요금이 다름).
- 시스템 프롬프트(캐릭터 시트)는 매 턴 같으므로 좋은 후보. 단, **접두사가 완전히 같아야** 하므로 프롬프트 순서가 중요하다: `고정 내용 → 가끔 바뀌는 내용(기억) → 매번 바뀌는 내용(최근 대화)`.
- 최소 토큰 길이, 캐시 유지 시간(TTL) 같은 조건이 있어서 짧은 프롬프트는 효과가 없을 수 있다. **제공업체별 조건을 공식 문서로 확인해야 한다.**

## 6. 응답의 `usage` 필드
- API 응답에는 실제 사용 토큰(입력/출력, 캐시 읽기/쓰기 등)이 들어 있다.
- 이 과제의 비용 측정은 전부 이 값으로 한다. 모든 호출(본 응답, 요약, 기억 추출, 재시도, 실패 포함)의 usage를 로그에 남기고 합산한다.

## 7. 비용 계산식
```
호출 비용 = 입력토큰 × 입력단가 + 캐시읽기토큰 × 캐시단가 + 출력토큰 × 출력단가
원화 비용 = 달러 비용 × 환율 (환율 기준일 명시)
턴당 평균 = (모든 호출 비용의 합) ÷ 완료된 턴 수
```
예시(가정값이며 실제 가격 아님, 설계 단계에서 공식 가격표로 교체할 것):
```
입력 $0.10/1M, 출력 $0.40/1M, 환율 1,400원/$
한 턴: 입력 2,000 + 출력 150 토큰
→ (2000×0.10 + 150×0.40) / 1,000,000 = $0.00026 ≈ 0.36원
```

## 8. 과제와의 연결
| 개념 | 과제에서의 의미 |
| --- | --- |
| stateless | 기억 = 우리가 매 턴 무엇을 프롬프트에 넣느냐 |
| 입력 누적 | 최근 N턴만 넣고 나머지는 기억으로 압축해야 함 |
| 캐싱 | 고정 접두사 설계로 반복 입력 비용 절감 |
| usage | 비용 실측의 유일한 근거 |
| 한국어 토큰 | 추정치를 영어 기준으로 잡으면 안 됨 |
